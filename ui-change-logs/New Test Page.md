# New Test Page — UI Change Log

One-line log of UI changes to the `new-test` screen in `prototypes/test-journey/index.html`. Newest at the bottom.

---

- 2026-04-24 — Implemented Group 1 feedback generation settings: split "Results and Feedback" into three subsections (Generation / Delivery / Display); added Tone, Length, Detail Level, and Feedback Event Type selectors; added Custom Prompt and Additional Context textareas with live word counts; renamed master toggle from "Generate report" to "Enable Feedback" (collapses generation fields when off); left-aligned all inputs and toggles under feedback generation; added `role="switch"` + `aria-checked` and keyboard activation for accessibility.
- 2026-04-24 — Restructured pill tabs from two to three: renamed "Settings" → "Test Settings" and "Grading" → "Grading Criteria"; added new "Feedback Settings" tab containing the three feedback subsections; renamed the inner section header "Grading" inside Test Settings to "Grading Variability Detection" to avoid clashing with the new Grading Criteria tab label.
- 2026-04-24 — Moved "Grading Variability Detection" setting out of Test Settings and into Grading Criteria (placed at the top of the "Grading Settings" section); extended the "Enable Feedback" master toggle so it now also hides the Feedback Delivery and Feedback Display subsections alongside the generation settings; updated the off-state notice copy to cover all feedback settings.
- 2026-04-24 — Removed the numeric step indicators (1, 2, 3) from the Test Settings / Grading Criteria / Feedback Settings pill tabs.
- 2026-04-28 — Restructured Feedback Settings → Feedback Generation as an either/or pairing: moved Feedback Event Type to the top, wrapped Tone/Length/Detail Level in a "Standard configuration" card, added an "Or take more control" divider, and placed Custom Prompt directly underneath in its own card with a richer multi-line placeholder example; populating the custom prompt now greys out and disables the standard config selects, highlights the custom card, and shows an inline "Replaced by your custom prompt below" banner.
- 2026-04-28 — Added an "Alternative view — tabbed" comparison card directly below the existing either/or pair (existing pair untouched) that renders Standard configuration and Custom prompt as two tabs inside a single card; populating the alt custom prompt shows an "Overridden" badge on the Standard tab, dims the Standard panel, disables its selects, and rings the card with the primary tint, mirroring the override behaviour of the sequential view for direct comparison.
- 2026-04-28 — Greyed out the Feedback Display subsection (header + all four display option toggles) by wrapping it in a `.feedback-display-greyed` container that applies opacity 0.45, `pointer-events:none`, and `aria-disabled="true"`; also set the inner switches' tabindex to -1 so they're not keyboard-reachable while greyed.
- 2026-04-28 — Group 2 Sub-section A: added "Feedback" third pill-tab to `submission-results`; built split-screen Feedback panel (left: submission doc + grade mini-table, right: feedback content); DRAFT/UNDER REVIEW/APPROVED/FAILED status badge; contenteditable rich-text region with formatting toolbar; Edit/Save draft/Approve action hierarchy with confirmation step; pending-skeleton + failed-with-retry states toggled by demo buttons; `aria-live` region for status announcements; all new styles use design tokens.
- 2026-04-28 — Group 2 Sub-section B: added collapsed "View history" version log panel (toggle in status bar, expandable list with version number / editor / timestamp / AI vs Current tags); added "Revert to original" bar + confirmation alertdialog (visible only when edited version exists, uses `icon-rotate-ccw`, restores AI content and collapses to single-version history on confirm); added Run 1 / Run 2 grade comparison section to left context pane (visible only when variability flagged, highlights mismatched scores in warn colour); extended demo state switcher with "Edited version", "Variability flagged", and "No edits" scenario buttons.
- 2026-04-28 — Group 2 Sub-section C: added "Quality signals" indicator row in the right content pane (below status bar, above history panel) with three pill chips — AI confidence (High/Medium/Low with shield-check/gauge/alert-triangle icon and success/warn/error token colours), Variability flag summary chip (No variability/Variability flagged — distinct from the Run 1/Run 2 comparison table in the left pane), and Review priority (Normal/High/Low with flag icon); chips are always visible in the ready state and hidden during pending/failed states; added "Low confidence", "High variability", and "High priority" demo scenario buttons; "High variability" also activates the left-pane grade comparison; "Ready" and "No edits" buttons reset all indicators to defaults; `aria-live` region reused for chip-change announcements.
- 2026-04-28 — Removed raw-hex `border-color` overrides (`#bbf7d0`, `#fde68a`, `#fca5a5`) from `.fb-confidence-*`, `.fb-variability-flagged`, and `.fb-priority-high` chip states — these violated the tokens-only rule; chips now rely on the base `border: 1px solid transparent` plus their token-driven `-100` fill and `-500/-600` text for visual distinction.
- 2026-04-28 — Removed all 11 demo/scenario buttons from the Feedback tab status bar and absorbed the bottom-right Studio/Candidate journey switcher into a new sticky **`.devbar`** developer-tools bar fixed to the bottom of the viewport (full-width, dark `var(--surface-900)` background, monospace font, 44px tall, intentionally styled to read as tooling rather than product); buttons are grouped under labels View / Feedback status / Feedback scenario / Quality signals, separated by thin dividers; existing `data-view-toggle` and `data-fb-demo` handlers continue to work unchanged. App shell height changed to `calc(100vh - var(--devbar-h))` so the bar never overlaps content. Convention from this point forward: **demo/scenario controls live ONLY in `.devbar`, never on prototype surfaces**.
- 2026-04-28 — Fixed broken asset paths after the file was relocated from `test-journey/` to `prototypes/test-journey/` — updated the `colors_and_type.css` `<link>`, the favicon `<link>`, and both wordmark `<img>` `src` attributes (Studio + Candidate sidebars) to use `../../` instead of `../` so they resolve from the new depth.
- 2026-04-28 — Surfaced "feedback ready for review" in two places on the test-journey prototype: (1) **Test list** — added a new "Feedback" column to the left of "Connections" (160px wide, sortable header) showing a warn-100 `feedback-ready-pill` with "N ready" when `feedbackReady > 0` and a muted em-dash otherwise; seeded `feedbackReady` counts on three test rows (Musango UX 5, Debugging and Enhancing 4, Fundamentals of Web Development 2). (2) **Test summary** — added a `.feedback-ready-banner` (warn-100 background, message-square icon in a white tile, primary "Review feedback" button) between the page header and the summary filters, with `aria-live="polite"`; the button uses `data-goto="submissions-list"` so the existing screen router takes the author to the submissions list. Also added an entry-hash handler on init that reads `?screen=` or `#name` and calls `showScreen()`, so external entry points (e.g. dashboard "Review feedback" buttons) can deep-link straight to a screen.
- 2026-04-29 — Renamed the existing `data-screen="new-test"` to `data-screen="new-test-submission"` (HTML + showScreen call); existing Submission new-test panel contents untouched. Replaced the plain "New" button in the test-list toolbar with a dropdown trigger (`#newTestBtn`) and menu (`#newTestMenu`) with six items — Likert / MCQ / Written / Submission / Simulation / [sep] / Import (Import is a no-op placeholder); menu opens on click, closes on outside-click or selection. Scoped the `data-builder-tab` click handler to the closest `.screen` so multiple builders' tabs no longer cross-fire.
- 2026-04-29 — Built four new per-type new-test settings screens — `new-test-likert`, `new-test-mcq`, `new-test-written`, `new-test-simulation` — each with the test-type's exact tab structure per the screenshots (Likert / MCQ / Written: Settings | Questions | Grading; Simulation: Simulation | Grading). Settings panels mirror each screenshot: Likert has General + Presentation + Proctoring (no Results and Feedback); MCQ and Written add a Results and Feedback section with a Generate report toggle; Simulation has a single General → Simulation Connection select. All form fields are interactive (text, textarea, select, file-upload drop zone, switches, number input). All Questions and Grading panels start in an **empty state** with "No questions" / "No grading categories" placeholders + an "Add Question" / "Add Category" dashed-outline button. Add Question on Likert/MCQ/Written renders a question card with QUESTION/CHOICES sub-tabs, Heading/Text content chips (×) and addable Image/External Link chips (+); Likert Choices uses a numbered option list with Add Option; MCQ/Written Choices uses option cards with a green correct-answer toggle, per-card delete, 0 pts label, and an Add Choice dashed card. Add Category renders a grading category card with collapsible levels, an Add Level button, and per-level percentage / name / description inputs. All "delete last item" actions restore the empty-state placeholder. New shared CSS patterns added: `.q-card`, `.q-subtabs`, `.q-chips`, `.opt-list`, `.choice-grid` / `.choice-card` (with `.is-correct`, `.is-add`), `.grade-cat` / `.grade-cat__level`, `.upload-drop`, `.builder-empty`, `.builder-add-row`, `.new-test-menu` (positions the existing `.menu` shell relative to the New button).
- 2026-04-30 — Added a top-of-column **Regrade submission** button (`#modRegradeBtn`, `.btn.sm.outline` with `icon-refresh-ccw`) inside the Moderation tab on the submission-results screen; placed inside a new `.mod-toolbar` wrapper at the top of the left grid column (above the Grading Category 1 / 2 panels), so the Submission panel on the right grid column does not shift.
- 2026-04-30 — Renamed the **Moderation** result-tab to **Review & Moderation** (uses `&amp;` entity); added a matching **Review & Moderation** `<h3>` section title to the left of the Regrade submission button inside `.mod-toolbar` (now `justify-content: space-between` so title sits left and button sits right).
- 2026-05-18 — Added click-to-toggle collapsible sidebar to both sidebar shells (studio + candidate): `js-sidebar-collapse` class on both collapse buttons wired by a shared IIFE at script-load; `setSidebarCollapsed()` adds `.is-collapsed` to all `.sidebar` elements and `.sidebar-collapsed` to `#app`; collapsed width 64px via CSS (`grid-template-columns` transitions from `240px 1fr` to `64px 1fr` in 150ms cubic-bezier); hidden in collapsed mode: wordmark, workspace name + chevron, `.sb-eyebrow`, `.ni-label`, `.badge`; icon column centred; `panel-left-close` → `panel-left-open` icon flip with `aria-label` + `aria-pressed` updates; `title` attribute added to all nav items as collapsed tooltip; state persisted to `localStorage` under key `traverse.sidebarCollapsed.test-journey`; restored on page load before first paint.
- 2026-05-18 — Fixed broken Lucide icon references that were rendering as empty `<i>` elements: `icon-more-horizontal` → `icon-ellipsis` (7 replacements; row overflow menus), `icon-alert-triangle` → `icon-triangle-alert` (3 replacements), `icon-check-circle` → `icon-circle-check` (2 replacements). All renamed in Lucide between earlier versions and 0.453.0. Backup at `prototypes/test-journey/index.html.pre-icon-rename-backup`.
- 2026-05-19 — Converted devbar tab groups into dropdowns via a runtime IIFE (same payload as dashboard / user-onboarding). The test-journey devbar uses explicit `.devbar__group` wrappers, so the converter picks those up directly: View / Feedback status / Feedback scenario / Quality signals each become a single dropdown trigger. Original `.devbar__btn` elements stay in the DOM (`display: none`) and continue to receive the delegated click. Trigger uses the same `.dev-dd` CSS family (`.devbar` scoped) — primary-500 highlight on active item, dark popover above the devbar.
