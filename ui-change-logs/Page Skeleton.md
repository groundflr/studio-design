# Page Skeleton — change log

- 2026-06-24 — Created `prototypes/page-skeleton/index.html`: a standalone page-layout conventions playground (NOT in the component library). Demonstrates the side menu panel (240px), top bar (56px), page header trio (overline → title → description, overline/description toggleable), tabs, the page surface (`--bg-page`) vs content-card surface (`--surface-0` / `--border-subtle` / radius 12px / `--shadow-sm`), a full-width container list card, and three content states switchable from a bottom control bar: Content, Empty (dashed ghost cards + centred empty-state, no character illustration), and Skeleton (opacity-pulse blocks). Every text element (`.ed`) is inline-editable: contenteditable, hover fades in input-field chrome (subtle bg + border + focus ring) with a ~150ms ease-in and constant padding compensated by negative margin so layout never shifts; blur saves the trimmed value (restores original if emptied); Enter saves single-line fields (multi-line copy marked `data-multiline`). Token-annotation captions toggle on/off; `?state=empty|skeleton` deep-links a state. On the design tokens + Lucide; self-contained (one file). Verified via headless Chrome (interactions + screenshots).
- 2026-06-24 — Added a "Card style" control (control bar): **Card** (default — every card has chrome) vs **On surface** — content sits directly on the page surface (transparent bg/border/shadow) and only the in-focus card (`.card.is-focus`, first card by default) or the hovered card lifts into the full card treatment (surface-0 + border-subtle + shadow-sm), with a 150ms ease transition and no layout shift (1px border kept transparent); the card-foot divider also fades in only on lift. Scoped to the content-state grid. Deep-link with `?cards=surface`. Verified via headless Chrome screenshot.
- 2026-06-29 — Rebuilt the shell using the library components in place of the hand-built markup: the side menu is now `<tv-sidebar>` (composing `<tv-nav-header>` wordmark + collapse toggle, two `<tv-nav-group>`s — Workspace: Overview/Tests/People/Library, Admin: Reports/Settings — and a `<tv-nav-user>` footer); the header trio + actions are `<tv-page-header>` (overline/title/description + inline secondary "Filter" / primary "New item"); the tabs are `<tv-tab-group>` + `<tv-tab>` (Overview/Activity/Members(6)/Settings, with icons). Removed the replaced `.sidebar`/`.sb-*`, `.page-header`/`.page-*` and `.tabs`/`.tab` CSS plus the `body.hide-*` rules. Rewired the bottom control bar: the **Overline**/**Description** toggles now add/remove the `overline`/`description` attributes on `<tv-page-header>` (re-renders), **Tabs** toggles the tab-group's display; tab switching and the sidebar collapse are now component-owned (tv-tab-group active state; tv-nav-header → tv-sidebar collapse propagation), and a click handler reflects `active` across nav items. Sidebar height is `calc(100vh - 44px)` so the footer user clears the control bar. Swapped the head Lucide CDN link for the vendored embedded `../../fonts/lucide/lucide.css` so the page's light-DOM icons render over `file://` too. Topbar, section heading, cards, list card, empty/skeleton states and `.ed` inline-edit (on the remaining hand-built text) unchanged. Verified via headless screenshots (content + empty states).
