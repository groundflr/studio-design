# Organisation Page — change log

- 2026-06-22 — Users tab: replaced the hand-authored role badges and status/state tags with the shared `<tv-status-tag>` web component across all three subtabs (members, invited, deactivated). Inferred kinds: admin-tier roles → `admin`, neutral-tier roles → `neutral`; Active → `active`, Deactivated → `deactivated`, Pending → `pending`, Cancelled → `cancelled`, Expired → `expired`. Scoped to the organisation screen's `users-main-col` only — workspace-settings, system-admin, and the peek rail (JS-rendered) left unchanged. Added the component-library loader to the page head. First production use of the component library in a prototype.

- 2026-07-15 — Invite architecture refactor (new users invited only at org level). Org **Invite users** modal reworked: single email `<input>` → multi-email token chips; single workspace `<select>` → multi-select workspace autocomplete chips; the Organisation-admin toggle now clears + disables the workspace picker (grants all current and future workspaces); one Workspace role applied uniformly to every selected workspace; **removed the Personal note** field; primary CTA now "Send invitations". Org **Invited** table rebuilt to **one row per person** (Email · Workspaces & roles · Sent · State · Actions) mirroring the members `role-line` pattern — Resend/Cancel act on the whole org invite, org-admin invites show "All workspaces"; Invited sub-tab chip 3→4. Org **Members** table: Org Owner/Admins (Tobias, Sarah, Marcus) collapsed from per-workspace lines to a single "All workspaces · Workspace Admin" line to reflect auto-membership. In-browser QA still pending (extension unavailable this session); inline scripts pass `node --check`.

- 2026-07-17 — Reworked the super-user "Add organisation" modal (#org-new-org-modal) to invite a client as Org Owner instead of auto-creating a default workspace and making the creator owner. Removed the "Default workspace name" field (new orgs now start with no workspace — the owner creates the first one after accepting); added "Owner's full name" (optional) + "Owner's email" (required, validated) fields. Primary CTA is now "Create & invite owner"; the created org row reads "No workspaces yet · Owner <name/email> invited"; success toast reads "Organisation created — owner invited". First step of the top-down Org Owner onboarding build.

- 2026-07-17 — Add-organisation modal: brought back the "Default workspace name" field (default workspace is a technical requirement — every org needs one to land in), kept alongside the new owner-invite fields. Create now makes org + default workspace + owner invite; the org row reads "1 workspace · Owner <name/email> invited". The owner's landing dashboard will prompt them to edit the default workspace, add a new workspace, or invite users (next build step).

- 2026-07-17 — Add-organisation modal: removed the "Owner's full name" field — the owner just gets an email invite and fills in their name/profile when they onboard. Modal is now Organisation name · Owner's email · Default workspace name; the org row uses the owner email as the label ("Owner <email> invited").
