# Test Journey — change log

- 2026-06-22 — Submission results view: converted the Results / Moderation / Feedback / History tabs from the sliding **pill** to the **underline** style (consistent with the builder + org/workspace tabs) with Lucide icons per tab. Removed the pill sliding-thumb span; its positioning JS now no-ops (already guarded) since active state is driven by `.active` on the underline tabs.

- 2026-06-22 — Converted the static status chips to `<tv-status-tag>`: "Draft" labels (draft-dot → kind `draft`, 5) and the "Overridden" badge (override-badge → kind `adjusted`, 1). Added the component-library loader to the page head. Left for a careful follow-up (JS-template / not-a-status): `fb-status-badge` (id, JS-toggled DRAFT/PUBLISHED), `q-card__draft-pill` (rendered in JS), `audit-tag`/`fb-history-tag` (JS templates), and the generic `pill-filled` rating chips (e.g. "Beginning"), `score-pill`, count chips (`changes-pill`, `feedback-ready-pill`), `q-chip`/`tabs-pill` (interactive/nav), and `ct-dot` (category dots).
- 2026-07-01 — Reworked the audit/history view. Made the settings-style **list view** the default (was the branch-graph timeline; timeline is now the alternate, toggled from the devbar "History view" group, relabelled List view / Timeline view). Replaced the multi-select event-type filter chips and the "Show full log / Hide full log" scope link with a single control row: a **segmented scope toggle** (Changes / All events) plus an **event-type dropdown** (All types + the types present in scope). Refactored the audit renderer into a reusable `createAuditView(root, getData)` factory with per-instance scope/type/selection state, driven by `[data-audit-timeline]` / `[data-audit-peek]` / `[data-audit-controls]` and a unified `AUDIT_META` map (system events hidden under "Changes", shown under "All events"). Retired the old global audit click-handler branches (expand / row-select / filter-chip / scope-toggle) — now owned per-instance.

- 2026-07-01 — Added a **Test History** tab (4th, after Summary / Submissions / Groups) on the test-summary and submissions-list screens, and a new `test-history` screen. It reuses the same audit layout, controls and behaviour as submission history but renders test-level events (`TEST_AUDIT`: population regrade, rubric updated, group regrade, feedback released, test published, unlocked for editing, test created) that apply to all submissions/candidates on the test.

- 2026-07-01 — Styled the audit event-type dropdown to sit inline next to the Changes / All events scope toggle. It was inheriting the full-width `.select` rule and wrapping to a second row; `.audit-type-select` now overrides to `width: auto`, 32px height, `surface-200` border, 12.5px/500 type and hover state to visually match the segmented control.

- 2026-07-06 — Added a third **History view** option — "Change log view" — to the devbar Audit history toggle (alongside List view / Timeline view), applying to both the submission History tab and the Test History screen via the shared `createAuditView`/`renderView` engine. It renders a single white bordered card on the standard `surface-50` background (no peek rail): a node timeline where each row leads with the event **statement** (primary), then a caption line of the committer name — or "System" — next to the date/time, with the rationale/detail in an inset quote box the same colour as the page background (`surface-50`, subtweet pattern). Nodes reuse `AUDIT_META` icons + type colours (grading = primary, feedback = info-blue, system = grey); grading events append the level change to the statement (e.g. "· Beginning → Proficient"). The existing Changes / All events scope toggle is retained but restyled from a segmented control into underline tabs in this view only. New JS: `changelogStatement`, `changelogDetail`, `renderChangelog` + an `is-changelog` branch in `renderView`. The other two views are untouched.

- 2026-07-20 — Built out the **Groups** tab (submission groups) and wired **Assign to Group** across the test-submission screens. The Groups tab now navigates to a new `groups-list` screen: a groups table (Name chip, Submissions grade-band tallies green/amber/red, Avg. Score, Open/Closed status control, row kebab) where each group row expands to a nested submissions sub-table (Submission · Submitted (graded) · Score · Ranking · Actions) with a "No submissions" empty state. Toolbar adds a **New Group** primary button that opens a `tv-modal-card` ("New group" → name input → Create); the group-row kebab offers Rename (reuses the same modal) / Delete. On the Submissions screen the row action menu's **Assign to Group** is now enabled (added a disabled **Re-process Submission** item for fidelity, swapped the icons to `circle-user` / `circle-x`) and opens an "Assign submission(s) to group" `tv-modal-card` using `tv-token-select` (mode="options") — the same autocomplete/searchable/scannable pick-list as the Add-user-to-workspace form. Group membership is a single source of truth (indices into `subs`): assigning reflects live in the Groups tab, the group tallies/avg, and a new group-chip in the Submissions table's Groups column; members can be removed via the sub-table row menu. New JS: `groups` model, `renderGroups`, `groupsForSub`, `openRowMenu`, `openNewGroupModal`, `openAssignModal` + modal wiring. Tone chips, dot colours and status all map to tokens (`--success`/`--cat-yellow`/`--error`/`--primary`).

- 2026-08-10 — Design-readiness system: added `data-status` to all 12 screen sections (test-list, test-summary, submissions-list `ready`; new-test-submission, new-test-likert/mcq/written/simulation, groups-list, test-history, submission-results, feedback-summary `wip`), added the `#prototype-manifest` JSON block (2 index entries) and `<tv-status-ribbon>` (top-right status ribbon; `?chrome=0` / devbar toggle to hide). No visual change to any screen itself.
